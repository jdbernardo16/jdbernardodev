## 1. Intent

Build a personal portfolio that converts external visitors into client inquiries for AI automation, AI integration, web development, and security work.

This is **not** a job-hunting CV. The primary business goal is to win clients outside the owner's current employment. The site must make a stranger believe, within the first screen, that Jaydee builds AI systems that do real operational work — and that he can also build and secure the software around them.

The previous portfolio (`jdbernardo16.github.io/portfolio-v2`) is a traditional developer portfolio: bio, one employer, a grid of websites. It undersells the current work. The new site leads with AI agents, anonymized client outcomes, and a senior technical point of view.

## 2. Goals

- Generate qualified inbound inquiries for AI automation and integration work.
- Present four credible AI case studies without exposing NDA-protected clients.
- Position Jaydee as a senior builder who also understands security (VAPT + incident response).
- Keep the site fast, accessible, and easy to update.
- Make a memorable first impression through purposeful interactivity, not decoration.

### Non-goals

- No blog, CMS, pricing page, or course/lead-magnet funnel at launch.
- No fabricated testimonials, logos, or client claims.
- No full 3D scroll journey at launch.
- No job-board/recruiter optimization as the primary purpose.
- No dependency on a backend database.

### Anti-goals

- A slow, GPU-heavy site that looks like a Three.js demo.
- Generic copy ("passionate developer," "digital experiences").
- Unverifiable claims or named clients without permission.
- Dark-purple AI gradients, glassmorphism, or crypto/web3 aesthetics.
- Animations that ignore `prefers-reduced-motion` or break keyboard use.

## 3. Audience

**Primary:** founders, SMB owners, and operators who need AI to automate a real workflow — grading, trading operations, order monitoring, customer inquiry handling.

**Secondary:** agencies or teams that need a senior full-stack developer for Vue/Nuxt, Node.js, Laravel, or Silverstripe delivery.

**Tertiary:** organizations that need VAPT, secure code review, or incident response.

The visitor is technically curious but not necessarily a developer. They care about outcomes, reliability, and whether the person can be trusted with production systems.

## 7. Interactive Design

### 7.1 Agent Flow Canvas (hero)

A live node graph representing the agent loop:

**Detect → Reason → Act → Notify**

- Rendered on an HTML5 2D canvas for crisp lines and predictable performance.
- Particles drift slowly; the cursor repels nearby nodes with a soft radius.
- Nodes pulse when hovered; labels appear for the active node.
- Clicking a node scrolls to the matching service or case study.
- A small caption explains the loop in plain language.
- Three.js is optional as an ambient depth layer only if the performance budget allows. The core experience must work without it.
- Mobile: simplified node graph with fewer particles and no cursor interaction; tap targets for nodes.
- `prefers-reduced-motion`: static diagram with the same labels and links.
- Pause animation when the canvas is offscreen or the tab is hidden.

### 7.2 Live Agent Console

A DOM-based panel inside Selected AI Work.

- Tabs: **Education**, **Trading**, **E-commerce**.
- Streams synthetic but representative log lines, e.g.:
  - `09:14:02  grade submitted → rubric matched → result recorded`
  - `09:14:07  MT5 position opened → stop set → owner notified`
  - `09:14:11  new order detected → inventory checked → owner notified`
- Controls: play/pause, speed (1x/2x), and a link to the full case study.
- No autoplay when reduced motion is set; a static first frame is shown instead.
- Uses `aria-live="off"` for the streaming area to avoid screen-reader spam; the current status is available as text.
- Must remain readable with JavaScript disabled: render a static sample log.

### 7.3 Micro-interactions

- **Command palette** — `⌘K` / `Ctrl+K` to jump to sections and case studies. Accessible dialog, focus trap, escape to close.
- **Magnetic CTA** — subtle pointer attraction on desktop only.
- **Scroll reveals** — staggered opacity/translate for cards; disabled under reduced motion.
- **Counters** — animate outcome numbers once when in view.
- **Card hover preview** — a small console-style preview on AI case-study cards; no layout shift.

All motion is purposeful, 200–600ms, ease-out. No scroll-jacking.

## 9. Technical Architecture

**Stack:**

- Nuxt 4 (latest stable), Vue 3, TypeScript strict.
- Tailwind CSS v4 with semantic tokens in `src/theme/main.css` or the Nuxt equivalent.
- GSAP + ScrollTrigger for scroll-linked reveals and counters.
- HTML5 Canvas for the Agent Flow hero.
- Three.js only as an optional ambient layer; lazy-loaded and feature-flagged.
- `@nuxt/image` for images, `@nuxt/fonts` for font loading, `@nuxtjs/seo` for metadata/sitemap/robots.
- `@vueuse/core` for pointer, visibility, and reduced-motion utilities.
- No database, no CMS. Case studies live in typed local data or Markdown content.

**Rendering:**

- Static generation (`nuxt generate`) deployable to Vercel, Netlify, or GitHub Pages.
- Client-only rendering for canvas/console effects; static HTML for all content.
- No layout shift from effects; reserve dimensions.

**Content:**

- Case studies in `content/work/*.md` or `data/work.ts`.
- Site copy in `data/site.ts`.
- The owner must be able to add a case study without touching component internals.

**Forms and contact:**

- Contact form posts to a Formspree endpoint configured via runtime env, with a `mailto:` fallback.
- Primary CTA: "Start a project" → contact section.
- Secondary CTA: "See the work" → selected work.
- Optional booking link (Calendly) to be supplied by owner.

**Analytics:**

- No analytics at launch unless the owner supplies a privacy-friendly account (Plausible or Umami). If added, track section views, case-study clicks, CTA clicks, and form submissions. No cookie banner for cookieless analytics.

## 16. V2 — Developer Theme and Agent Lab (approved 2026-11-07)

The first implementation was technically sound but visually contained: the agent canvas lived in a single square, and the developer theme was mostly typography. V2 makes the whole site behave like a working developer environment, with a playable game as the front door.

### 16.1 Reference direction

Researched references:

- **Andrew McCarthy** — a dark field of tiny symbols that shifts with movement; project names scramble into place.
- **Diogo Correia** — particle background behind a content-first hero.
- **A1 interactive development collection** — custom cursor, WebGL/Three.js, data visualisation, but important text stays in the DOM.
- **Terminal/IDE portfolios** (LiveTerm, VS Code-inspired portfolios) — shell chrome, file tabs, status bars, command lines.
- **Programming puzzle games** — `while True: learn()` node graphs, TIS-100/Shenzhen I/O industrial terminal UI, Zachtronics-style run/log panels.
- **Type** — Geist Mono / Berkeley Mono / JetBrains Mono for chrome and code; Inter for body. Keep Instrument Serif for the owner's name and large editorial headlines to avoid a generic all-mono look.

### 16.2 Concept: “The portfolio is a live system”

- **Page-wide ambient graph** — a fixed, low-opacity canvas behind all content: nodes, hairline connections, cursor parallax, scroll drift. It is ambient, not the main event. Pauses offscreen/hidden, caps DPR, and renders a static grid under reduced motion. All readable content stays in the DOM.
- **Agent Lab hero game** — the main interactive piece. A terminal-window panel beside the headline. The visitor builds an agent pipeline for a mission by clicking nodes into slots, runs it, and reads the log. Correct order unlocks the matching case study. Three missions: E-commerce, Education, Trading. Forgiving: wrong order gives a specific hint, never a dead end. Keyboard accessible (buttons, not drag-only).
- **Terminal chrome** — a fixed bottom status bar (`● agent online`, current section, local time, `⌘K`) and a command line behind `⌘K`. Commands actually navigate and filter: `help`, `ls`, `open <slug>`, `whoami`, `contact`, `missions`, `clear`.
- **Case studies as repos** — repo header, file tabs (`README`, `flow`, `logs`, `outcome`), line-numbered code/log blocks, and a replay control. Still fully server-rendered and readable without JS.
- **Micro-interactions** — text scramble on section headings, custom cursor ring/crosshair on fine pointers, magnetic CTAs, staggered scroll reveals, and a subtle grid/grain overlay.

### 16.3 Visual system changes

- Primary accent shifts to **terminal signal green**; amber remains for warnings/estimates; cyan for links/info; magenta used sparingly for syntax.
- Background: near-black graphite with a faint 1px grid and grain.
- Chrome: terminal title bars, path labels (`~/agent-lab`, `~/work/education-agent`), status dots, line numbers.
- Keep the Instrument Serif display face for the name and major statements; use mono for metadata, labels, logs, and controls.
- No fake macOS window clone, no purple gradients, no glassmorphism.

### 16.4 Guardrails

- A non-technical client must never need the terminal or the game to understand the offer, the work, or the contact path.
- The game is a demonstration, not a gate. Every case study is reachable by scrolling.
- The ambient canvas is decorative and must not affect LCP, CLS, readability, or battery life.
- No invented claims. The 5x grading figure stays labeled as an owner estimate.
- No agency names. The government incident stays "a government agency website."
- Critical fixes from the v1 review land in the same pass: empty-endpoint contact failure, mobile menu keyboard access, cross-route header links, double-suffixed titles, missing web-work section, and unverified copy.

## 17. V3 — Bug Smash Hero (approved 2026-11-07)

The Agent Lab and Three.js pipeline were scrapped. The hero now uses **Bug Smash**, a small arcade game that fits the developer theme without requiring the visitor to learn an AI workflow.

### The game

- A terminal-window panel titled `~/bug-smash`.
- A 3×3 grid of source files (`auth.ts`, `api.ts`, `db.ts`, `ui.tsx`, `cache.ts`, `queue.ts`, `mail.ts`, `pay.ts`, `deploy.sh`).
- Press **run build**. Bugs spawn in random files and expire after roughly 0.7–1.3 seconds.
- Click/tap a bug, or press its cell number `1–9`, to squash it.
- Score, combo multiplier, 30-second build timer, and three lives.
- Missed bugs "ship" and cost a life. At zero lives or zero seconds, the build ends.
- Result screen: bugs squashed, score, best score (localStorage), replay, and a `Start a project` CTA.
- Under `prefers-reduced-motion`, the game is paused with a static panel and a direct contact CTA.
- No JavaScript: the game is optional; the headline, services, case studies, and contact remain readable.
- No Three.js, no WebGL, no canvas: DOM-only for performance and accessibility.

### Why it replaced Agent Lab

- It is a real game, not a guided demo.
- It is instantly understandable without reading a mission brief.
- It works with mouse, touch, and keyboard.
- It is short enough to replay and light enough to keep the hero fast.
- It keeps the developer theme without pretending the visitor is building an AI agent.
