# Portfolio 2026 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy a Nuxt 4 portfolio that converts visitors into AI, web, and security client inquiries.

**Architecture:** A statically generated Nuxt 4 site with a single-page home, four data-driven case-study routes, a privacy page, and a small set of interactive components (canvas agent flow, live console, command palette) that degrade gracefully. Content lives in typed local data; no CMS or database.

**Tech Stack:** Nuxt 4.6, Vue 3.5, TypeScript strict, Tailwind CSS v4, GSAP + ScrollTrigger, HTML5 Canvas, optional lazy Three.js, Vitest 5 + @nuxt/test-utils 4 + Playwright 1.65.

**Spec:** `docs/superpowers/specs/2026-11-07-portfolio-2026-design.md`

## Global Constraints

- **Claims:** the `5x` grading figure is an owner-stated estimate and must be labeled as such. No other invented metrics, percentages, testimonials, or client outcomes.
- **Confidentiality:** never render the strings `PNA` or `DOJ`. Use "a government agency website." The four web clients may be named as plain text; no logos without separate permission.
- **Hermes:** describe it as "an open-source AI agent runtime." It may be named.
- **Phone:** do not display `0956-093-4971` publicly.
- **Analytics:** none at launch.
- **Privacy:** a `/privacy` page and a consent checkbox on the contact form are required.
- **Tailwind:** semantic tokens in `app/assets/css/main.css` using OKLCH. No hex colors or arbitrary values in class names.
- **Performance:** Lighthouse 90+ on mobile; LCP < 2.5s; CLS < 0.1.
- **Accessibility:** keyboard navigation, visible focus, AA contrast, reduced-motion equivalents.
- **Static generation:** `pnpm generate` must succeed.
- **Package manager:** `pnpm`.
- **Commits:** one per task, conventional commit messages.

## Review Focus

These are the failure modes most likely to hurt a real visitor. Each has a test in the task that owns the code.

1. **Reduced motion** — a visitor with `prefers-reduced-motion` must get a complete static equivalent of the canvas and console, not a blank or frozen animation.
2. **Low-end mobile** — the canvas must scale particle count, cap DPR, and pause offscreen so scrolling stays smooth on a 390px phone.
3. **Keyboard-only** — the mobile menu and command palette must open, trap focus, close on Escape, and restore focus.
4. **Confidentiality** — no agency names, unapproved logos, or invented claims in rendered HTML or metadata.
5. **No JavaScript / failed hydration** — all case studies, contact email, and core copy must remain readable without client-side JS.

- `addNode(id)` appends to the pipeline (max 4). `removeNode(index)` removes a node. `run()` validates the exact solution; wrong order sets `status: 'error'` with a hint log; correct sets `status: 'success'` and a success log. `reset()` clears. `nextMission()` advances and resets.
